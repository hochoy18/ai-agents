## 1. Agent 核心架构与组件

> 面试的绝对核心区。面试官会重点考察你对 **Agent 运转循环（Loop）** 的理解，四大组件都是围绕这个循环展开的。

### 1.1 Agent 运转循环（Loop）

- 循环的基本结构：感知输入 → 规划/推理 → 行动（工具调用）→ 观察结果 → 更新状态，直至任务完成
- 终止条件设计：任务完成判定、最大步数 / Token 预算限制、异常与超时退出
- 循环中的状态管理：每一步的上下文如何累积、裁剪与传递

### 1.2 规划（Planning）—— Agent 的"大脑"

- **任务分解（Task Decomposition）**：把复杂目标拆解为可执行的子任务
- **动态重规划（Re-planning）**：执行中遇到失败 / 新信息时如何调整计划
- **自我反思（Self-Reflection / Critic）机制**：对自身输出与执行轨迹的检查、纠错与迭代

### 1.3 记忆（Memory）

**短期记忆**

- 上下文窗口的管理
- 滑动窗口策略
- 递归摘要提取（对话 / 轨迹压缩）

**长期记忆**

- 向量数据库的写入 / 更新策略
- 记忆分层机制：事件型（Episodic）与语义型（Semantic）
- 记忆冲突解决：新旧记忆矛盾时的取舍与合并

### 1.4 工具调用（Tool Use / Action）

- **Function Calling 原理与 Schema 设计**：模型如何决策调用、参数如何约束、错误如何回传
- **MCP（Model Context Protocol）与传统 Function Calling 的区别**：协议化 / 标准化的工具接入 vs 应用内自定义工具

### 1.5 角色设定（Persona）

- 角色指令约束：身份、能力边界、行为准则的设定与遵循

## 2. Agent 范式与选型

### 2.1 主流范式对比

- **ReAct**：推理（Reasoning）与行动（Acting）交替融合
- **Plan-and-Execute**：先整体规划、再逐步执行
- 各范式的优缺点、适用场景与失败模式对比

### 2.2 技术边界判断（高频面试题）

什么时候用普通 Prompt，什么时候用 Workflow（工作流），什么时候才真正需要上 Agent：

| 方案 | 适用场景 | 核心特征 |
| --- | --- | --- |
| Prompt | 单轮 / 少轮即可完成的任务 | 无外部交互，纯生成 |
| Workflow | 步骤固定、路径可预知的任务 | 流程由人编排，LLM 是节点 |
| Agent | 路径不确定、需动态决策的任务 | 流程由模型驱动，自主循环 |

- 判断依据：任务复杂度、路径确定性、成本与延迟、可控性与可靠性要求

## 3. Multi-Agent 多智能体协作

### 3.1 主流框架对比

- **LangChain / LangGraph**：图结构编排、状态机式流转
- **AutoGen**：对话驱动的多 Agent 协作
- **MetaGPT**：SOP（标准作业流程）驱动的角色分工

### 3.2 协作机制设计

- **防死锁设计**：循环等待、互相推诿、无限对话的检测与打断
- **通信拓扑**：中心化（Supervisor / Orchestrator）vs 去中心化（对等协作）vs 层级式
- **上下文隔离**：各 Agent 的私有上下文与共享信息边界，避免污染与泄露

## 4. Agent 评估

### 4.1 评估维度

- **端到端结果**：任务成功率、目标达成度
- **过程 / 轨迹质量**：规划合理性、工具调用准确率、冗余步骤
- **效率与成本**：步数、Token 消耗、延迟
- **鲁棒性与安全**：异常输入、工具失败、越权行为的处理

### 4.2 评估方法

- 规则断言：可程序化验证的结果（状态检查、数值比对）
- LLM-as-a-Judge：用模型评估开放式输出与执行轨迹
- 人工标注：抽样评审与标注一致性

### 4.3 常用基准（Benchmark）

- AgentBench、GAIA、τ-bench、SWE-bench 等：各自考察的能力侧重与局限

### 4.4 工程实践

- 评估集构建：从真实流量 / 失败案例中沉淀测试用例
- 回归测试：Prompt / 模型 / 工具变更后的自动化评估
- 线上监控：成功率、成本、异常轨迹的持续观测与告警
